# M2 in-game check: the roster, the alts, the member card, the contacts and the silent co-play recording

The offline tests and the network simulator prove that the code agrees with our assumptions about the client; this checklist proves that the client agrees with the code. It is the **exit check of milestone M2** and it is **not done yet**: nobody has run this version on WoW Forever. When it passes, `v0.2.0` is tagged for the owner's guild ([docs/RELEASING.md](../RELEASING.md)); until then there is no release. (`v0.1.0` waits for [the M1 check](M1.md) in the same way: run that one first, or both together.)

**Exit criterion of M2:** in game, clicking a member shows all the characters of their account and their contacts (you and a second player with the addon).

Report the results with the *In-game test report* issue form (or in the table at the end), and tick the M2.7 box in [M2-roster.md](../roadmap/M2-roster.md).

## What you need

- WoW Forever with a character **in a guild** (a guild of any size; a big one is the best test of speed).
- **Two characters of the same Battle.net account on the same realm, both with the addon**, at least one in the guild (an alt outside the guild is useful too: step 5). Log each one in once, with the addon, for a minute or more.
- A **second client with the addon** in the same guild (a second account or a guildmate): steps 5–8. If it is a guildmate, a private message with the results of `/accord debug` is enough: it contains no names.
- On the PC: `tools/local.ini` with your AddOns folder (as for the M1 check), then from the repository folder:

```bash
python -I -X utf8 tools/fetch_libs.py
```

```bash
python -I -X utf8 tools/install_addon.py
```

  Run the second command again after every update. `/accord debug` never contains player, guild, BattleTag or Discord names, so its text is safe to paste.

## 1. Loading and `/accord debug`

1. Start the game (or `/reload`). **No Lua error**, no chat message at login. `/accord help` now also lists `settings`.
2. `/accord debug`, Ctrl+C, paste into the report. Check these lines (copy them into the result):
   - **Features**: `clubProfessions`, `clubDiscord`, `battleTag`, `groupGUIDs`: each `available`, `unknown` or `missing`, and its note;
   - **APIs**: the new ones are `guild.CanViewOfficerNote`, `player.GetPlayerInfoByGUID`: `available` or `missing`?
   - **Roster**: members, online, "source roster+club" (or "roster" only, or "club" only), how many professions are *native*;
   - **Accounts**: your groups; **Contacts**; **CoPlay**: "recording", no errors;
   - **Saved data**: `no problems`.

## 2. The Roster table (SPEC-05 §1)

1. `/accord roster` opens the window on the Roster view; the guild window's Accord tab shows it too, and **Pop out** moves it.
2. Columns: Name (class colour), Lvl, Class, Rank, Zone, Last online, Profession 1, Profession 2, Contacts, Addon. Note anything cut off, overlapping or unreadable, in the **tab** and in the **window**, and at the window's minimum size.
3. Click each header: it sorts, a second click reverses, the arrow shows the direction. Members with nothing in a column (no profession) are always at the bottom.
4. Type in the search box at the top (a name, then a profession name): the table filters at once; empty it again.
5. Filters: **Online**, **Mains only**, the **Class**, **Rank** and **Profession** menus (each lists only what the guild has; choosing one filters; the first entry clears it), then **Columns**: hide Zone, `/reload`, open again: still hidden. *Default columns* brings it back.
6. Scroll with the mouse wheel and by clicking the bar on the right. **With a big guild** note: how many members, whether scrolling and opening are smooth, any freeze when the guild window refreshes.
7. **By account** shows one row per player, a **+** next to accounts with alts; click it to show the alts.
8. Leave the table open and change a public note in Blizzard's own Roster (officer): the Accord table updates within a few seconds; the game's own panel keeps working.
9. Class colours: are the names coloured?

## 3. Professions from the game (check S2)

1. Look at the Profession 1 / 2 columns for members who **do not** have the addon (ask a guildmate). Filled with names and ranks, or empty? Note both numbers: native count in `/accord debug` and what you see.
2. Open the card of such a member: the profession lines say *(from the game)*. For a member with the addon and nothing from the game, they say *(shared by the member…)* (this needs M3 to fill them; until then "No profession data yet").
3. Your own character always shows your professions, *(read from your own character)* if the game does not give them natively.

## 4. The member card (SPEC-05 §2)

1. Click a row: the card opens **beside** the table in a wide panel, **over** it (with *Back*) in a narrow one (the tab). Note the width at which it changes (about 760 px), any text that overflows, and whether long lines wrap.
2. It shows zone, last online or *Online now*, rank, the **public note**, and the **officers' note only if you can read officers' notes**. Check on an **officer** and on a **member without that permission**: the second must not see the officers' note, even if the first sees it. Note what happens.
3. Close it with ✕ / *Back*: the room goes back to the table and the selection is cleared.
4. Click a member who left the guild (or a character listed only by an alt, step 5): the card says so.

## 5. The characters of an account (SPEC-05 §3; needs the two characters and the second client)

1. Log in with the **first character** (in the guild) for a minute, then log out; log in with the **second** (same account, same realm). Wait **two minutes**.
2. On the **second client**: open the card of either character: it lists **the other one** under *Characters of the same account*, with its level and class, the main labelled **main** (by default the highest level).
3. The same two characters are one row in the **By account** view, with the alt under the main.
4. Do the same with an **alt that is not in the guild**: it appears on the card in grey, *not in guild*, and clicking it opens its own card.
5. On the card of your own character, a **[Make this my main]** line (only on your own characters that are not the main): click it; the other client shows the new main within a minute or two.
6. **A note hint:** put `main: <name of the first character>` in the public note of a guildmate who does **not** use the addon: his row joins the first character's account, with *declared in the note*. Tell us if you would write the notes the other way round (SPEC-10, question Q7).
7. `/accord debug` → *Accounts*: "published" is small (one or two), not growing with every `/reload`.

## 6. Contacts (SPEC-05 §4; needs the second client)

1. `/accord settings` shows your **BattleTag** (or says the game did not give it) and the Discord field. Type your Discord user name, **Save**: "Saved and shared with your guild." Try a link or a name with a space: it is refused.
2. On the second client, the card of your character shows **Battle.net: …** and **Discord: …** within a minute; the table's *Contacts* column says BT and DC.
3. Click a contact: a small box opens with the text **already selected**; Ctrl+C copies it, Esc closes it. Typing in the box changes nothing.
4. If the game fills the Discord field natively (question 2): the card says *(from the game)* for members who never typed it.
5. **[Add BattleTag friend]** on a guildmate who agrees: the chat says "Friend request sent to …" and the other player receives a friend request in Battle.net. Try it **in combat** as well. If it does not arrive, or the chat says the game did not accept it, write down exactly what the chat says.
6. The button is not on your own card.

## 7. Co-play recording (SPEC-07 §3.1; needs a guildmate in your group)

Nothing is shown; only the debug counts.

1. Form a party with a guildmate (the second client, with or without the addon). Stay together **at least 5 minutes**.
2. `/accord debug` → *CoPlay*: "recording, N count(s)" grows by one each minute, "N with guild members" follows, "1 pair(s) today" (2 members), "0 unreadable".
3. Add a third guildmate: pairs become 3. Add a non-guild player: nothing changes.
4. Enter a **dungeon** (or raid) with the party and wait 5 minutes: the counts keep growing. If "unreadable" grows instead, the GUIDs are hidden inside instances (question 8): note it, with the `groupGUIDs` feature line.
5. Log out (or wait an hour). On the **second client**, `/accord debug` → *Store* shows `coplay` records (one per observer): the minutes were shared. Two players with the addon in the same group must **not** double the minutes (this is covered offline; here just see that nothing looks wrong).
6. After midnight (realm time) the first count of the new day publishes yesterday's minutes: if you play across midnight, report whether it looks right.

## 8. Two clients: the data converges (needs the second client)

1. Both clients in the guild. `/accord debug` on each: *Sync* shows peers heard, *Store* shows `accounts` and `contacts` records growing to one per player with the addon, `refused 0`.
2. `/reload` one client, wait two minutes: it still has all of them (it asks for what it lost).
3. Log one client out for 10 minutes and back in: it catches up with the changes (a new Discord name, a new main) within a few minutes.

## 9. Taint and combat (short; the M1 list is the full one)

After using the Roster table and the card in the guild window's Accord tab: do two protected actions in **Blizzard's own** guild window (edit a note; promote or invite as an officer). Nothing should say "action blocked" or raise a Lua error. Open the table and the card during combat (training dummy): no errors.

## What to report if something does not work

| Symptom | What to send |
|---|---|
| Lua error | the error text (error frame or BugSack) and what you did |
| The table is slow or freezes | the guild size, the window it was in, and `/accord debug` |
| The professions or the Discord column are empty for everybody | `/accord debug`: the *Features* and *Roster* lines |
| An alt does not appear on the card | `/accord debug` on both clients (*Accounts* and *Store* lines) and how long you waited |
| The friend request does nothing | the exact text the chat prints |
| *CoPlay* counts nothing in a group | `/accord debug` *CoPlay* and *Features* lines, party or raid, instance or not |
| Something looks wrong on screen | a screenshot (blur names if you like) |
