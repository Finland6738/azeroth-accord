# M1 in-game check: load, the Accord tab, the window, `/accord debug`, the sync

The offline tests and the network simulator prove that the code agrees with our assumptions about the client; this checklist proves that the client agrees with the code. It is the **exit check of milestone M1** and it is **not done yet**: nobody has run the addon on WoW Forever. When it passes, `v0.1.0` is tagged for the owner's guild ([docs/RELEASING.md](../RELEASING.md)); until then there is no release.

Report the results with the *In-game test report* issue form (or in the table at the end), and tick the M1.9 box in [M1-foundations.md](../roadmap/M1-foundations.md).

## What you need

- WoW Forever with a character **in a guild**. Steps 4–5 are best done with an officer (who can promote and invite). Step 8 needs a **second client with the addon** in the same guild: a second account, or a guildmate.
- On the PC: `tools/local.ini` with your AddOns folder (the same file the M0 probe uses; copy `tools/local.example.ini` if it is missing). Then, from the repository folder:

```bash
python -I -X utf8 tools/fetch_libs.py
```

```bash
python -I -X utf8 tools/install_addon.py
```

  The first command downloads the libraries once; the second copies `AzerothAccord/` into the AddOns folder (run it again after every update). The probe `AzAc_Probe` can stay installed: the two do not interfere.

`/accord debug` never contains player, guild, BattleTag or Discord names, so its text is safe to paste. Replace any name you write yourself with `<player>`.

## 1. Loading

1. Start the game (or `/reload`). At the character screen, *AddOns* lists **Azeroth Accord**; if it says "out of date", enable *Load out of date AddOns*.
2. In game: **no Lua error** and **no chat message** at login.
3. `/accord help` lists `/accord`, `roster`, `professions`, `reputation`, `bank`, `debug`, `help`. With an Italian client the texts are in Italian.
4. `/accord roster` answers "This part is coming soon" (no view exists in M1).

## 2. `/accord debug`

1. `/accord debug` opens a box with the report already selected. Press Ctrl+C, paste it somewhere: the whole text must come along. Typing in the box changes nothing; *Close* and Esc close it.
2. In the report check, and copy into your result:
   - the header: `interface: 16001`, `project id: … (WoW Forever)`;
   - **Sending**: `allowed` (out of instances);
   - **Compat → Features**: the state of each line (`available`, `missing`, `unknown`) and its note. Open the guild window once and run `/accord debug` again: `guildTab` must become `[available] … attached with template …` (write down which template);
   - **APIs**: how many are `missing`, `restricted` or `error`, and which;
   - **Saved data**: `no problems`, and the sizes.
3. Paste the whole report into the issue: it is the most useful single thing for the next milestones.

## 3. The Accord tab (SPEC-04 §1, check S1 again with the real code)

1. Open the guild window (default key `J`). Under Chat, Roster, Guild Benefits and Guild Info there is a fifth tab with the Accord logo. Note size, icon and spacing compared with the others. From M6.18 the tab is a themed tile (a rounded square, the accent ring when it is open), not Blizzard's tab look.
2. Hover it: the tooltip says *Azeroth Accord*.
3. Click it: a dark panel covers the content with "Welcome to Azeroth Accord" and a top bar with `0 guildmate(s) with Accord online · no data received yet` (or a higher number, see step 8) and **Pop out**. Note whether the panel covers exactly the content area or spills over the edges.
4. Click each Blizzard tab in turn: the panel disappears and the game's content works normally. Click Accord again between each.
5. Switch the window to its small size (the button at the top right) with the Accord panel open: the tab disappears with the panel. Back to the large size: the tab is there again.
6. If you are in another community, select it in the list on the left: the tab disappears; select the guild again: it comes back.
7. Close the window with the panel open and open it again: the panel is closed, the tab is there.
8. `/reload` with the guild window open, then open it again: the tab is there and works.

## 4. Taint: the guild window keeps working

After using the Accord tab at least once in the session, do the **protected actions in Blizzard's guild window**, one at a time, and after each check that it worked and that **no** "action blocked" / "interface action failed" message or Lua error appeared:

- promote or demote a member (officer);
- invite a player to the guild (officer);
- edit a member note and an officer note;
- change a rank permission, or (officer) remove a member only if you are happy to.

## 5. Combat

1. Fight a training dummy with the guild window open: click Accord and the Blizzard tabs during combat. No errors, the panel opens and closes.
2. During combat type `/accord` twice: the window opens and closes.

## 6. The standalone window

1. `/accord` opens the window with the same welcome text; `/acc` closes it. There is no *Pop out* button in the window.
2. Move it (drag the title), resize it (bottom-right corner), `/reload`, `/accord`: same place and size.
3. Esc closes it.
4. From the guild window, Accord tab → **Pop out**: the panel moves into the window; clicking the Accord tab brings it back.
5. **AddOn Compartment** (the addon list button by the minimap): *Azeroth Accord* is listed with the Accord logo; hovering shows the hint and the sync state; clicking opens and closes the window.
6. **Key binding**: *Options → Keybindings → AddOns*: "Open or close Azeroth Accord"; bind a key and try it.
7. On a character **without a guild**: `/accord` says "You are not in a guild." and opens nothing; the guild window has no Accord tab.

## 7. Saved data

1. Log out and back in on the same character, then on another character of the same account: no error, `/accord debug` → *Saved data* says `no problems` on both.
2. After a full logout, the file `AzerothAccord.lua` exists in `<WoW folder>/_forever_/WTF/Account/<account>/SavedVariables/`. Do not send it (it is your data); just say whether it is there and its size.

## 8. Two clients: the sync is alive (needs a second client with the addon)

In M1 nothing writes shared data yet (characters, contacts and recipes come with M2 and M3), so this only checks that the two addons hear each other.

1. Both clients log in (or `/reload`) in the same guild. Wait one minute.
2. `/accord debug` on each: in the **Sync** section `peer(s) with the addon heard recently` is 1 (2 with three clients), `HELLO sent 1, heard 1` or more; in **Transport**: `normal`, nothing `failed`; **Codec**: `rejected 0`.
3. The panel's top bar says `1 guildmate(s) with Accord online`.
4. If one client is an **officer**: note the `officerAddonChannel` line in Features on both clients (it stays `unknown` in M1: nothing is sent on `OFFICER` yet; just record it).
5. Enter a dungeon on one client and wait for the next HELLO (up to 20 minutes) or `/reload` inside: no error; the *Sending* line may say `held` while the game restricts addon messages, and the messages go out after.

## What to report if something does not work

| Symptom | What to send |
|---|---|
| Lua error at login or on a click | the error text (from the error frame or BugSack) and what you did |
| No Accord tab in the guild window | `/accord debug`, especially the `guildTab` feature line and the *Guild tab* section |
| The tab is misplaced, looks wrong or the panel spills over | a screenshot of the guild window |
| "Action blocked" or "interface action failed" after a protected action | which action, whether the Accord tab had been used, and the exact message |
| The window does not remember its place | whether the game was closed normally |
| `peer(s) ... heard recently` stays 0 with two clients | `/accord debug` from both clients |
