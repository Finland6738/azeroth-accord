# M3 in-game check: the professions, the recipe lists, "who can craft" and craft requests

The offline tests and the network simulator prove that the code agrees with our assumptions about the client; this checklist proves that the client agrees with the code. It is the **exit check of milestone M3** and it is **not done yet**: nobody has run this version on WoW Forever. When it passes, `v0.3.0` is tagged for the owner's guild ([docs/RELEASING.md](../RELEASING.md)); until then there is no release. (`v0.1.0` and `v0.2.0` wait for [the M1 check](M1.md) and [the M2 check](M2.md) in the same way: run those first, or all together.)

**Exit criterion of M3:** in game, you open a guildmate's recipes from the roster and find who can craft an item.

Report the results with the *In-game test report* issue form (or in the table at the end), and tick the M3.6 box in [M3-professions.md](../roadmap/M3-professions.md).

## What you need

- WoW Forever with a character **in a guild**, and the roster of M2 working ([the M2 check](M2.md)).
- **A second client with the addon** in the same guild (a second account or a guildmate), who knows at least one profession with recipes and opens the profession window once with the addon (steps 2, 4 and 5). If it is a guildmate, a private message with the results of `/accord debug` is enough: it contains no names.
- A guildmate **without the addon** who has a profession (step 3).
- On the PC: `tools/local.ini` with your AddOns folder (as for the M1 check), then from the repository folder:

```bash
python -I -X utf8 tools/fetch_libs.py
```

```bash
python -I -X utf8 tools/install_addon.py
```

  Run the second command again after every update. `/accord debug` never contains player, guild, BattleTag or Discord names, so its text is safe to paste.

## What is not known yet (this is what the check is for)

Every one of these is built with a fallback; the check says which side of each the real client is on. Write the answer in the report.

**The M0.4 probe results are not in yet.** The native source (the game's own guild recipe directory) is built behind a capability check and the lists shared by the members' addons are a complete fallback that works alone. This check settles which one is the main source; the choice is written in [SPEC-06 §1.1](../specs/SPEC-06-professions-recipes.md) (Italian) once the answers are here.

## 1. Loading and `/accord debug`

1. Start the game (or `/reload`). **No Lua error**, no chat message at login.
2. `/accord debug`, Ctrl+C, paste into the report. Check these lines (copy them into the result):
   - **Features**: `guildRecipesNative` and `ownRecipes`: `available`, `unknown` or `missing`, and the note;
   - **APIs**: `tradeskill.GetAllRecipeIDs`, `tradeskill.GetFilteredRecipeIDs`, `tradeskill.GetCategoryInfo`, `spell.GetSpellInfo`, `spell.GetSpellLink`, `spell.RequestLoadSpellData`: `available` or `missing`?
   - **Recipes**: "native source usable / not usable (reason)", the counters;
   - **RecipeScan**, **Crafters**: no errors;
   - **Saved data**: `no problems`.

## 2. Your own recipes (S4, PRO-06)

1. With a character that has a profession with recipes, **open the profession window** (the one Blizzard shows). Wait 3 seconds.
2. `/accord debug` → *RecipeScan*: "1 scan(s), 1 published" and "last: published N recipe(s) of skill line …". **Does N match the recipes you know** (not the whole list of the profession)? Note both numbers.
3. Type something in the profession window's search box, or turn a filter on, and look at *RecipeScan* again: the count of published recipes must **not shrink**.
4. Open the window again, change nothing: "unchanged", no new publication. Craft something that raises your skill: after the 10-minute pause a new publication follows (*deferred* first).
5. Open a second profession and Cooking (or First Aid): each gets a record. Cooking is not a profession cell of the roster.
6. `/reload` and open the window again: no duplicate, the revision grows only if something changed.
7. In the roster, find **your own character**: the profession cell reads `Name rank/max`; click it: your own list opens, *Source: your own profession window*.

## 3. The native source (S3; needs a member without the addon)

1. `/accord debug` → Features `guildRecipesNative`: `unknown` ("enabled, no answer seen yet") means the client says the directory is on; `missing` says why not.
2. In the roster click the profession cell of a guildmate **without the addon**: *Source: the game* with a list, or the message that nobody has the list. Write down which.
3. `/accord debug` → *Recipes*: "native queries N, answers N, timeouts N, unreadable N". After the click `answers` must be at least 1 if the server fills the directory; the Features line should now say `available`. If `unreadable` grows and the feature note says *bitfield*, tell us: the shape of the answer needs to be decoded (send the *Recipes* line).
4. Try an **offline** member as well: answer, or a timeout after 8 seconds?
5. Open the recipes of five different members in a row: the queries go out one at a time (2 seconds apart) and nothing freezes.

## 4. The recipe list (PRO-01, PRO-02, PRO-03)

1. In the roster, hover a profession cell: the tooltip names the profession, **where it comes from and how old it is**, and says to click. Click: the **Professions** view opens on that member, with *Back to roster* and *Who can craft* at the top.
2. The header reads `Member - Profession rank/max` and the source and age. Compare the age with reality.
3. Each row has an **icon and a name**. Do any rows read "Recipe 1234" and then change? Do some never change? Hover a recipe: the game's own tooltip.
4. Type in the search box at the top of the panel: the list filters by recipe name. Empty it again.
5. **Category** menu: *Recipes I know / do not know* appear when you have your own list of the same profession; check them on a member who knows more than you. Any other categories? Are some names coloured orange/yellow/green/grey?
6. Open the card of a member (click the row in the roster) and click a profession line: the same list opens.
7. Open the list of a member whose list nobody has (offline, no addon): the **message says why and what to ask**. Wording clear? Does *Back to roster* work in the tab and in the window?
8. Does the list **fill in by itself** when the data arrives (the second client opens its profession window while you look)?

## 5. Two clients: the lists travel (S3 not needed)

1. On the second client, open the profession window once. Within a minute, on your client: *Store* in `/accord debug` shows a `recipes` record, and opening that member's list shows *Source: shared by the member's addon*.
2. Log the second client out, log in later: you still see its list (an officer's copy, or when it is back). If you are an **officer**, check that an offline member's list comes from you.
3. Open the list of a member who is **online and has the addon** but whose list you have never seen: it appears within a few seconds (the addon whispered them a request). `/accord debug` → *Sync*: "set requests: asked N".
4. `/accord debug` on both: *Sync* `refused 0`.

## 6. Who can craft (PRO-04)

1. `/accord professions`: the view opens on **Who can craft**. Type a potion or an item at least two letters long in the search box.
2. The recipes that match are listed; under each one the members who can craft it, **online first**, with their profession, rank and the age of their list; the characters of one player together. Try **Online only**.
3. Search for an item by a name that is **not** the spell name (for example a bar or a bag), and paste an **item link** (Shift-click an item into the box): is it found?
4. Click a crafter: their list opens. The **Back to roster** button returns to this search (the list was opened from here); the *Who can craft* button does the same.
5. With a **big guild**: how long does the first search take, and does the game stutter? (The offline measurement is about 250 ms.)

## 7. Request craft (PRO-05)

1. On a recipe of an **online** member (in their list, or under the recipe in *Who can craft*) click **Request craft**: the **chat box opens** with `/w Name Hello! Could you craft [recipe] for me? Thank you!` and nothing is sent. Is the recipe a clickable link? Press Enter to send it.
2. The button is **not** on your own recipes, on offline members, or on the recipe's header row.
3. Try it with the game in combat and during a chat restriction: does the box still open?

## 8. Taint and combat (short; the M1 list is the full one)

After using the view in the guild window's Accord tab: do two protected actions in **Blizzard's own** guild window (edit a note; promote or invite as an officer). Nothing should say "action blocked" or raise a Lua error. Open the list and search during combat: no errors.

## What to report if something does not work

| Symptom | What to send |
|---|---|
| Lua error | the error text (error frame or BugSack) and what you did |
| My own list is not published, or has the wrong number of recipes | `/accord debug`: *RecipeScan*, Features `ownRecipes`, and the numbers you counted |
| A member's list never appears | `/accord debug`: *Recipes*, *Sync* lines on both clients, who was online |
| The native source says `missing` or `unreadable` | the *Recipes* line and the Features `guildRecipesNative` note |
| Rows stay "Recipe 1234" | `/accord debug` APIs `spell.*` and how many rows |
| "Who can craft" finds nothing you expect | what you typed and the item's name in the game |
| Request craft does nothing | what the chat says |
| Something looks wrong on screen | a screenshot (blur names if you like) |
